# 安全开发规范

> 状态：Active
> 更新日期：2026-07-03

## 1. 安全目标

Mobile Agent 能够影响真实设备，所有模型、客户端输入和设备内容均按不可信处理。安全默认值优先于便利性。

## 2. 信任边界

- 模型输出：不可信
- 用户自然语言：不可信参数来源
- 外部 MCP/HTTP Client：不可信
- UI 树、截图元数据与设备输出：不可信
- Skill Manifest：可读取但执行代码必须受信任
- Desktop UI：不能直接获得系统命令能力

## 3. 命令执行

- 仅 ADB Runner 等批准模块可以创建系统子进程。
- 使用绝对或经过验证的可执行文件路径。
- 参数必须来自类型安全构造器。
- 禁止 shell、管道、重定向、命令替换和 eval。
- 限制超时、输出大小、输入长度和并发。
- stderr 经过脱敏和分类后才可进入日志。

## 4. 路径和文件

- 用户文件必须规范化并限制在授权路径。
- 防止 `..`、符号链接和大小写差异逃逸。
- Artifact 文件名由系统生成，不使用设备或模型提供的原始名称。
- 禁止默认读取用户主目录、SSH、浏览器或系统凭据目录。

## 5. API 与 IPC

- Local API 只监听 loopback。
- 每次 Runtime 启动使用随机短期令牌。
- 校验 Origin 和 Content-Type。
- 变更操作进行认证、幂等和参数校验。
- WebSocket 建立时认证，断线重连不能绕过权限。
- MCP 调用与桌面端使用同一 Policy Engine。
- MCP stdio 子进程只允许连接固定 HTTP loopback Runtime 地址，令牌通过进程环境注入，不写入仓库、
  stdout、错误或任务记录。
- MCP Host 必须在传入 `confirmed=true` 前展示目标和参数并取得用户确认；布尔字段不能降低 Runtime
  注册表定义的风险，Policy Engine 仍可拒绝调用。
- MCP stdout 只允许 JSON-RPC，Tool 输入限制大小和调用频率，Runtime 响应必须限制、解析并脱敏。

## 6. 风险策略

- Low：可逆观察与导航，可按策略自动执行。
- Medium：改变普通状态或输入文本，默认需要策略判断。
- High：安装、卸载、清除数据、账号或隐私修改，必须明确确认。
- Prohibited：支付、验证码绕过、任意 Shell 等，拒绝执行。

风险等级由注册表定义，模型不得指定或降低。

## 7. 数据与隐私

- 截图、UI 树和任务数据默认只在本地。
- 用户应能查看、导出和删除记录。
- 默认设置保留期限，过期后安全清理。
- 调用云模型前明确展示数据边界。
- 密钥保存于系统 Keychain，日志只记录 provider 和配置状态。
- 测试 fixture 必须去除账号、手机号、路径和设备唯一标识。

## 8. Prompt Injection

设备屏幕和 UI 文本可能包含针对 Agent 的恶意指令。

- 屏幕内容是环境数据，不是系统指令。
- Agent 只能遵循用户目标、系统策略和注册 Tool。
- 页面文字不能扩大权限或修改风险策略。
- 涉及跨应用、外发数据和高风险动作时重新授权。

## 9. 审计

记录：

- 谁或哪个客户端发起任务
- 目标设备
- Tool/Skill 与参数摘要
- Policy 决策和确认
- 执行结果与错误码
- 关键 Observation 和 Artifact 引用

审计记录本身也要最小化敏感数据。

## 10. 安全审查触发条件

以下变更必须单独安全审查：

- 新系统命令或新平台 Adapter
- 文件上传、安装、卸载或清除数据
- 远程 API 或网络监听范围变化
- 第三方 Skill 执行
- 云端模型或遥测
- 认证、Keychain、权限或确认策略变化
