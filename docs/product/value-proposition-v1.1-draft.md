## 1. 一句话价值主张

### 中文

> ThumbAgent 让任何大模型都能安全地操作真实手机：动作受策略约束、结果经确定性验证、全程证据留痕、数据不出本机。

### 英文

> ThumbAgent gives any LLM a trusted thumb on real devices: policy-gated actions, runtime-verified outcomes, full evidence trails, and local-first data.

### 价值公式

```text
（任意模型的大脑）×（可信的执行与证据层）×（本地安全边界）
```

模型半年一换代，ThumbAgent 不绑定任何一个模型；模型越强，敢让它操作真实设备
的人越需要策略、验证与证据这一层。价值随模型进步而增长，而不是被模型吃掉。

## 2. 三层价值支柱

### 2.1 可信执行（给 AI 一只可信的手）

- 所有动作经 Schema / Capability / Policy 三重校验，绑定明确设备
- 高风险操作两阶段授权；支付、验证码、任意 Shell 永久禁止
- 完成状态由 Runtime 依据前台应用、UI 状态、系统状态确定性判定，不采信模型自述

### 2.2 可审计证据（知道它做了什么、为什么失败）

- 每个动作前后留 Observation；日志、性能快照、诊断证据包带 SHA-256 清单
- 执行时间线可回放；人工接管区间计入事件流
- 失败可解释：错误码、失败步骤、最后现场

### 2.3 本地安全边界（数据不出本机）

- 无云端账号、无遥测；密钥只进系统钥匙串
- 模型 Provider 可替换、可关闭；调用云模型前明示屏幕内容将离开本机
- Artifact 留存策略 + 范围绑定的两阶段清理

## 3. 行业判断（2026 年中，支撑上述主张）

- GUI Agent 成功率快速爬升（AndroidWorld 头部已达 73–81%，触及人类基线），
  「大脑」正在商品化；执行层、验证层、安全层成为稀缺能力。
- 行业共识从纯视觉点击转向**混合动作空间**（程序状态 / API / Intent 优先，
  视觉点击兜底），可靠性与成本收益已被 CoAct-1、StateAct、MAI-UI 等验证。
- 评测与验证器成为研究与应用热点；Agent Skills 格式攻击面被实证，
  具备成熟策略层的执行平台获得差异化优势。
- 新 benchmark（MobileWorld、AndroidDaily、RealMobile）转向真实设备、
  多 App、长程任务——正是 ThumbAgent 的工程纵深方向。

## 4. V1.1 能力清单（建议）

按优先级排序；每项标注与现有架构的关系。

### P0 — 混合动作空间（Iter 候选：ITER-0058）

| 能力 | 说明 | 架构影响 |
| --- | --- | --- |
| Intent / Deep Link 直达 | 能用 `am start` / deep link 到达的页面不点屏幕；Adapter 固定参数数组 | 新增 Tool，走既有 Policy |
| 通知栏读取 | 只读 Tool，支撑验证与诊断场景 | 新增 Tool + Capability |
| CJK 文本输入 helper | 受控输入法 APK（AIDL），补齐非 ASCII 输入短板 | 设备端 helper，需 ADR |
| 剪贴板读写 | 只读为主，写入按 Medium 风险 | 新增 Tool |

### P1 — 评测能力产品化

| 能力 | 说明 | 架构影响 |
| --- | --- | --- |
| 自然语言场景 → 版本化测试 Suite | QA 用户描述场景即生成可回归用例 | 复用 GoalCompiler + Evaluation |
| 系统状态判定器扩展 | 成功判定不止前台包名/Selector，覆盖数据库、文件、通知等系统状态 | Evaluation 域扩展 |
| 回归报告 | 模型/App 改版后一键回归，输出成功率、耗时、失败诊断 | 只读聚合，已有雏形（ITER-0042） |

### P2 — 感知与输入补短板

| 能力 | 说明 | 架构影响 |
| --- | --- | --- |
| 视觉 grounding 兜底 | 自绘控件 / WebView 缺语义时，本地小模型（4B–7B 开源）输出坐标候选，仍走 Policy 与验证 | Provider 可插拔，需 ADR |
| 设备端感知 helper | Accessibility Service 提供原子性更强、覆盖 WebView 的 Observation | 中期，需 ADR |

### P3 — 从工具到平台

| 能力 | 说明 | 架构影响 |
| --- | --- | --- |
| Teach & Repeat | 用户演示一遍 → 生成可确认的可复用 Skill 草案 | 需设计 Skill 草案确认协议 |
| 情节记忆 | 任务结束沉淀「某 App 某页面怎么走」为可复用知识，注入后续规划 | Agent 层扩展 |

### P4 — 规模化门票

| 能力 | 说明 | 架构影响 |
| --- | --- | --- |
| 多设备并行执行 | 同目标分发多机型，统一汇总对比 | Lease 已按设备隔离，扩展路径清晰 |
| iOS 适配器原型 | 明确能力降级呈现，不伪装能力一致 | 独立 Adapter，不改上层协议 |

## 5. 明确不做（V1.1 非目标）

- 自训基础 GUI 模型
- 支付、验证码、账号安全等高风险消费场景
- 云端账号、团队空间、遥测上传
- 第三方 Skill 分发市场（Teach & Repeat 仅限用户自有 Skill；开放生态需先完成签名与审计设计）
- iOS / 鸿蒙完整能力对齐

## 6. 待决策问题

1. **首要用户锚点**：下一阶段主打「QA 回归评测」还是「AI 设备工程师（诊断/证据）」？
   两者共享底座，但叙事与获客路径不同。
2. **视觉兜底选型**：本地小模型（隐私好、有部署成本）vs 云端多模态（现成但
   改变本地优先默认值）——建议做成 Provider 可插拔，默认关闭。
3. **开源价值捕获**：Apache-2.0 下的长期路径（影响力 / 托管服务 / 企业版能力）需要尽早明确。
4. **CJK helper 的形态**：随应用分发的输入法 APK 涉及安装授权与签名分发，需评估合规与维护成本。
