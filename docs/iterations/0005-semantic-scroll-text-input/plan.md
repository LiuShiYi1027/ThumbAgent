# ITER-0005: Semantic Scroll & Text Input

> 状态：Completed
> 更新日期：2026-07-08
> Owner：Codex

## 目标

在 ITER-0004 已具备语义定位与安全点击的基础上，补齐 V1 中最小可用的滚动与文本输入能力，使 Runtime 能在当前屏幕找不到目标时进行有界语义滚动查找，并能在明确授权下向安全文本框输入非敏感文本。

本迭代要证明：

> Agent 不只会点击当前屏幕上已经出现的元素，也能在受控范围内继续查找目标，并对可编辑字段完成可验证、可审计的输入动作。

## 背景

ITER-0004 完成了 UI hierarchy 解析、Selector、唯一匹配、可点击祖先解析、`input.tap_element` 和 `settings.navigate` 的真机闭环。但真实移动页面经常存在两个新问题：

- 目标元素不在首屏，需要滚动后才能出现。
- 部分任务需要输入文本，例如设置页搜索、测试 App 表单、诊断关键词过滤。

如果直接暴露裸 `swipe` 或 `input text`，模型很容易变成“猜坐标 + 盲输入”。因此本迭代必须继续坚持 Contract-first、Policy-first 和 Observe–Act–Verify：滚动必须有方向、范围和停止条件；输入必须绑定可编辑目标、风险策略和后置验证。

## 范围

- 定义滚动、文本输入和语义查找相关 Contract。
- 实现 `input.swipe` Tool：
  - 使用屏幕比例或安全区域生成坐标。
  - 限制方向、距离、持续时间和屏幕边界。
  - Medium 风险，默认需要确认。
- 实现 `input.text` Tool：
  - 仅向当前聚焦输入框或通过语义 Selector 定位的可编辑节点输入。
  - 限制文本长度和字符类别。
  - 拒绝密码、验证码、支付、账号安全等敏感输入场景。
  - Medium 风险，默认需要确认。
- 实现有界语义滚动查找：
  - 每轮 Observe 后尝试匹配 Selector。
  - 找不到时按指定方向滚动。
  - 通过 UI tree、截图 hash 或节点摘要检测无进展。
  - 达到最大滚动次数、超时或无进展阈值时停止。
- 实现一个安全示范 Skill：
  - 优先选择系统设置内的只读搜索或测试页面输入场景。
  - 不提交表单，不切换开关，不修改系统设置。
  - 输出每轮观察、滚动、输入和验证结果。
- 更新 Runtime API、Fake Adapter、自动化测试和真机验收记录。

## 非目标

- OCR、视觉 grounding 或复杂图像理解。
- 通用自然语言 Agent Loop。
- 长按、拖拽、多指手势和复杂手势编排。
- 提交表单、发送消息、发布内容、支付、验证码或密码输入。
- 修改系统开关、账号、安全、隐私或权限设置。
- iOS、鸿蒙真实 Adapter。
- 多设备并行调度。

## 安全边界

- 真机滚动只能用于查找元素或进入无副作用页面，不用于绕过权限、风控或安全提示。
- 真机输入只允许非敏感、可撤销、不会自动提交的短文本。
- 文本输入不得包含密码、验证码、密钥、手机号、身份证号、银行卡号或其他高敏个人信息。
- 不对 `EditText` 以外的节点输入；无法确认目标可编辑时拒绝。
- 不在键盘候选、发送、保存、删除、确认、支付等控件上执行自动点击。
- 每个写动作后必须重新 Observe，并以结构化 UI 证据验证。
- 匹配不唯一、滚动无进展、输入后无法验证时停止，不继续猜测。

## 依赖

- ITER-0002 的标准 Observation、截图和 UI hierarchy artifact。
- ITER-0003 的 Tool Registry、Policy Engine、Action Result 和基础动作。
- ITER-0004 的 UI Selector、UiLocator、`input.tap_element` 和安全导航经验。
- Android Adapter 的 ADB 参数数组执行能力。

## 风险

- Android 厂商键盘、输入法和页面结构差异可能导致输入结果不稳定。
- `adb shell input text` 对空格、特殊字符和非 ASCII 文本支持有限，可能需要分阶段处理。
- 滚动动作结果可能因页面惯性、嵌套滚动容器和系统动画变得不确定。
- UIAutomator 不一定准确标记所有可编辑节点，需要严格拒绝不确定场景。
- 真机测试容易触达真实设置页面，因此验收必须选取不会修改设备状态的任务。
