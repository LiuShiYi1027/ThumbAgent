# ITER-0018 复盘

> 状态：Completed
> 日期：2026-07-10

## 完成内容

本迭代把模型 Provider 从“代码里存在”推进到“产品界面可见”：用户打开本地 Web UI 时，可以看到当前模型 Provider 是否启用、当前 provider/model，以及是否存在密钥引用。

## 关键取舍

- 选择只读状态面板，不在 Web UI 中编辑模型配置，避免过早引入密钥管理和配置持久化问题。
- 状态 API 不返回 `api_key_ref` 原文，只返回布尔值，降低本地页面、日志或截图泄露风险。
- Runtime 仍不自动启用真实 Provider，保持 V1 默认安全路径。

## 后续建议

下一步可以进入“模型配置文件 + 本地密钥解析器”的设计迭代，但需要先明确：

- 配置文件位置与迁移策略；
- Keychain 或本地 SecretResolver 的边界；
- UI 中启用模型前的显式确认与风险说明；
- 失败时如何在任务报告中呈现模型不可用，而不是静默回退。
